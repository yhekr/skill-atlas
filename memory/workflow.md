## Проверки и публикация

Обязательные команды и условия готовности находятся в [AGENTS.md](../AGENTS.md). Базовый набор: `dotnet format --verify-no-changes --no-restore`, `dotnet build -c Release`, `dotnet test -c Release --no-build`. При изменении упаковки — pack/publish. Тесты должны быть детерминированными, без сети; Git-интеграция использует временные локальные репозитории.

[GitHub Actions](../.github/workflows/ci.yml) проверяет Windows и Ubuntu: форматирование, сборку, .NET-тесты, PowerShell-тесты наблюдателя, Node-тесты фильтра, упаковку CLI и публикацию Web. Bash-тесты sandbox выполняются на Ubuntu. TRX и пакеты сохраняются как artifacts.

По подтверждённому запросу 2026-09-30 добавлена задача браузерных записей и визуальных сравнений: [Run-BrowserTests.ps1](../scripts/Run-BrowserTests.ps1) запускает Playwright в одном закреплённом Docker-образе локально/на CI, сохраняет видео/trace каждого теста и сравнивает reviewed PNG. `-Mode update` — только локальное осознанное обновление эталонов; `-Mode prove` проверяет падение от тестовой CSS-подмены и успешное восстановление без изменения исходников. Скачиваемый CI artifact `browser-recordings-and-screenshots` хранится 14 дней. Фиксированные API-ответы не заменяют отдельные тесты scanner/API; подробнее в [README](../README.md#запись-браузерных-тестов-и-сравнение-скриншотов).

По просьбе пользователя [.githooks/post-commit](../.githooks/post-commit) запускает [Run-CI.ps1](../scripts/Run-CI.ps1) после каждого коммита. Он отправляет захваченный SHA обычным push и проверяет `ci.yml` для этого SHA/ветки каждые **120 секунд**, максимум 45 минут. Повторный ручной push во время работы наблюдателя не нужен.

- Хук устанавливается [Install-GitHooks.ps1](../scripts/Install-GitHooks.ps1) локально в каждом клоне; Git не переносит настройку `core.hooksPath` при клонировании. Явный пропуск одного запуска — `SKILL_ATLAS_SKIP_CI=1`.
- Наблюдатель переиспользует существующий run; при задержке запуска от push может вызвать `workflow_dispatch`, предварительно проверив SHA удалённой ветки. Force push не выполняется.
- Только `success` означает успех; failure, cancelled и timeout — ошибки. Проверять точный SHA, а не только зелёный badge или соседний коммит.
- Лог и JSON находятся в `ci-watch` внутри каталога, который возвращает `git rev-parse --absolute-git-dir`. Это особенно важно для worktree, где `.git` — файл.
- Автоматическое завершение `git merge` может не вызвать post-commit. Для filter использовались `git merge --no-ff --no-commit filter` и отдельный `git commit`; при отсутствии хука запускать наблюдатель согласно AGENTS.

Полные инструкции запуска и авторизации — в [README](../README.md). Результат CI публикуем в ответе со ссылкой; не создаём бесконечные коммиты памяти только ради записи CI предыдущего коммита.
